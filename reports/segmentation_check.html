ReRx Pilot — Segmentation Configuration Check

HRCE-1, Plate 25 · 24 sites, 6 wells · Cellpose cross-check

What this report shows

Before freezing CellProfiler's nuclei thresholding settings, the pipeline ran an independent cross-check: Cellpose's generic nuclei model (which does not use CellProfiler's threshold-based approach at all) against CellProfiler's own nuclei counts, on a small, representative sample of real pilot sites. This is a methods/decision report — it explains why one pipeline setting changed, not a biology result. See docs/src/segmentation-config-check.md for the full reusable procedure and plan.md's segmentation review section for the complete investigation, including the post-fix re-validation numbers.

The finding: two dim wells, badly over-segmented

This comparison is the data that surfaced the problem, run with CellProfiler's default Otsu thresholding. Two wells (AA08, E08) were measurably dimmer than the other four sampled wells and came out 3-7× over Cellpose's independent count, while every other well matched Cellpose within about ±25%.

This gap is why CellProfiler's own MeasureImageQuality module (DNA channel only) is now embedded in production (pipelines/rxrx19a.cppipe) and checked automatically by rerx.validate.check_image_quality on every run — so a future dim-well problem surfaces without needing to rerun this Cellpose investigation by hand. Cellpose itself is a one-time diagnostic tool, never a production dependency.
